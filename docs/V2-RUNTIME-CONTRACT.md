## Owner commands

GET `/api/control` returns version 2, policy revision, company lifecycle/weight/maxConcurrent, receipts, and individual capabilities. POST `/api/control/commands` accepts `{id,expectedRevision,expiresAt,type,businessId,allocation}`. Types are company.stop/pause/resume, allocation.set, global.stop/resume. Allocation is `{weight:0..100,maxConcurrent:0..12}` with optional tokenLimit/requestLimit/spendLimitMicros (nonnegative integer or null) and allowedProviders (distinct exact provider IDs or null). These ceilings are cumulative owner budgets, not subscription quotas or automatic reset windows. Uditus is capped at one concurrent admission. Commands must expire within five minutes; revision conflicts fail. Same-origin cookie, exact Origin, JSON content type, and X-Armis-Owner:1 are required. No arbitrary shell endpoint exists.

Policy lives outside generated text in `.armis/owner-policy.json` (override ARMIS_OWNER_POLICY_PATH). Writes atomically replace a private file. Command IDs deduplicate; conflicting reuse fails. Stop persists its admission fence before remote cancellation. Buildings remain stopping when cancellation or residual usage is unconfirmed. Pending resume/allocation acknowledgment fences new admission. Reservation records survive restart until reconciliation. GET control discloses a separate ownerReserve for owner-services chat/status, independent of HQ company lifecycle. HQ shutdown preserves that reserve; global stop cancels/fences it as well. Its requests and consumption remain separately attributed, never hidden inside HQ.

## Supported Hermes executor binding

Set server-only ARMIS_EXECUTOR_URL and ARMIS_EXECUTOR_TOKEN only after implementing a supported installed Hermes bridge. No guessed Hermes CLI runs. The HTTP bridge exposes GET capabilities, POST policy, POST cancel and POST chat relative to that URL, bearer-authenticated. Capabilities return `{verified:true,covered:[...],chat:true,recipient}`. Every covered path must be actually intercepted: owner-chat, executives, workers, delegations, schedules, retries, provider-adapters, tool-processes. Missing paths keep company control, allocation and chat disabled. Advertisement is a bridge assertion; installed acceptance tests must independently establish truth.

Policy response is `{applied:true}` only after all execution gates apply the revision. Cancel response is `{stopped:true,residualUsage:false}` only after all owned processes and uncancelled cloud usage reconcile. Chat returns `{reply}` from the real configured recipient. Viewer chat reserves HQ capacity and respects global stop; durable message IDs prevent retry re-execution after restart. Conversations remain in private local policy storage, never telemetry or readiness reports.

The executor must acquire POST `/api/admission` `{id,businessId,provider,tokens,costMicros}` before each provider request using a separate server-only ARMIS_GATE_TOKEN bearer binding. Reserve upper bounds, and enforce them at the provider adapter; under-reserving cannot enforce a hard ceiling. Release via POST `/api/release` `{id,usage:{tokens,costMicros}}` only after outcome reconciliation. Admission atomically checks consumed plus outstanding request/token/spend ceilings, provider routes, stop fences, zero allocation, concurrency and explicit attribution. Missing actual usage conservatively charges reservations with usageProvenance=reservation_upper_bound; observed actual reconciliation is locally_measured. Confirmed cancellation does not erase already incurred consumption. Weight is scheduling preference, not a provider entitlement; upstream quota windows and actual provider maximums remain executor responsibilities. This service cannot halt unmanaged execution outside these gates. Do not claim complete coverage until installed tests prove every path.

## Installation and checks

`npm run test:runtime` uses fake executors for shutdown persistence, residual cancellation, coverage, expiry, idempotence, allocation, serialization, cookie auth and CSRF. `npm run check:mac` validates actual installed loopback transport and writes connection-readiness.json. Fixture tests are not Mac evidence.

The configured Linux updater may invoke `npm run deploy:mac -- --apply`. It requires reconciled clean main, performs fast-forward update/build/runtime tests, restarts existing armis-viewer user service, checks transport and writes `.armis/deployment-readiness.json`. Existing dirty Mac branch is preserved and rejected, never reset. Previous dist/revision are retained and restored on failed activation. A Git pull alone does not install the supported executor or restart services. Installed Mac local modifications still need review; no Mac deployment or executor coverage has been verified from this PC.
